## 動作確認（テスト用グループ・チャンネル・プロジェクト）

| 確認 | 結果 |
|---|---|
| 2人分の伝票メッセージ | 約20秒で伝票2件。Slack 2投稿、Asana 2タスク。担当に LINE の表示名、未収あり（4万円）は冒頭表示・タスク名・未収ステータス・未収残高に反映 |
| メンション無しの雑談 | 受け口で無視（処理なし） |
| 「@null よろしく」 | 「解析できないメッセージ」として要確認 |
| 未登録グループでの @null | 起票せず、グループ ID を Slack に通知 |
| 処理の途中失敗 | Cloud Tasks の再試行で回復（古い版に当たって5回失敗 → 更新後に処理） |
| 課金停止（dry） | 費用0円の通知では何もしない。5円の通知で Slack に dry 通知、停止の権限あり |
| Claude の費用 | 1通 約 2,100 入力・100〜200 出力トークン（Haiku）＝約¥0.04 |

## 分かったこと・決めたこと

- Cloud Run では `/healthz` のような末尾が `z` のパスは予約されていて 404 になる（動作に影響なし。監視に使うなら別のパスにする）。
- 組織の「ドメインで制限された共有」（`iam.allowedPolicyMemberDomains`）により、Google の予算通知用アカウントに Pub/Sub の権限を付けられない。
  - そのため、予算を billing-guard につなげない。
  - 本人には組織の権限が無く、特権管理者への依頼が必要。依頼は本人が行う。
  - 接続できるまでは、予算のメール通知（1・50・100円）と上限設定（各サービス最大1台、画像は保存しない）で運用する。
  - 接続できたら `infra/setup.py guard-budget` → `guard-live` を実行する。
- billing-guard のサービスアカウントは、請求先の状態を読む権限が無い（403）。停止の判定には影響しないよう処理した。
