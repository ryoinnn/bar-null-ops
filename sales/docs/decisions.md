## 起票のトリガー（2026-10-10 変更。最優先）

- 伝票の起票は、**Bot へのメンション（@Bot。表示名は後で決める）で始まる伝票メッセージ**（日付・顧客名・金額・備考）をトリガーにする。
- 伝票の画像は、人が見て確認するために送られるもの。**システムでは一切扱わない**（取得しない、読み取らない、保存しない、Slack や Asana に添付しない）。
- そのため依頼書の次の部分は不要になる。
  - 画像の伝票判定・OCR（§5.1-3）、画像とテキストのペアリング（§5.1-5）、Cloud Storage への画像保存
  - アラート「内容メッセージ未着」「伝票画像未着」「伝票判定不能」、同一画像による重複検知
  - Asana と Slack への画像の添付
- メンションの判定は LINE の Webhook の `mention.mentionees[].isSelf`（Bot 自身へのメンションなら true）で行う。
  - 一覧から選ばずに「@Bot名」と手で打った場合は、メンション情報が付かない。そのため、本文が設定した Bot 名で始まる場合も対象にする。
  - Bot の表示名を後で変えても、`isSelf` で判定するので動作は変わらない。
- メンションの無いメッセージは処理しない（保存も Claude への送信もしない）。
- 訂正・未収の回収報告・現金のまとめ入金の報告も、同じく @Bot で始まるメッセージで受け付ける（2026-10-10 了承）。
- @Bot を付け忘れたメッセージは起票されない。それでよい（2026-10-10 本人）。
- 代わりに **「Square に決済があるのに伝票が無い」** ときは、その事象が起きたときだけ Slack で通知する（日次のまとめは出さない。2026-10-10 本人）。
- 1通に顧客が複数並んでいれば、顧客ごとに伝票を作る（例: 顧客Bさま・顧客Cさま）。
- メッセージの解析には Claude（Haiku）を使う。解析できなかった場合は Slack に「要確認」を出す。
- LINE への返信（「受け付けました」・解析エラーの案内）は任意機能で、既定は OFF（reply は無料。必要になったら ON にする）。

## そのほかの決定

### 課金の防止（GCP）
- 予算（¥100）を作り、通知を Pub/Sub で受ける小さな関数を置く。費用が出たら、プロジェクトから請求先アカウントを外して、すべてのサービスを止める（Google 公式の手順「通知で課金を無効にする」）。
- 止める前に Slack とメールで知らせる。再開は、原因を確認してから手動で請求先アカウントをつなぎ直す。
- 課金データの反映には数時間の遅れがあるため、止まるまでに数円かかる可能性はゼロにはできない。
- 請求先を外したまま長く放置すると、Google がリソースを削除することがある。止まったら早めに対応する。
- あわせて、上限も設定する: Cloud Run の最大インスタンス数 1、Cloud Tasks の送信レート、Secret Manager は6バージョン以内、Artifact Registry は最新2つ、ログの除外設定。
- Claude API の費用は GCP とは別。Anthropic Console で売上管理用の API キーに使用上限を設定できる（任意）。

### 伝票の単位
- システム上の「伝票」（slip_id、Slack スレッド、Asana タスクの単位）は、メッセージ内の **顧客1件**。

### メンションと担当者
- ★付きのアラートと未収リマインドでは、桝本（Slack `U0A51TDCCEN`）をメンションする。
- LINE の送信者は、通知文と Asana の「担当」欄（テキスト）に表示名を載せるだけにする。staff の Slack／Asana ユーザーとの紐付けは作らない。

### メッセージの種類
- `slip_content`（伝票の内容）、`correction`（訂正）、`unpaid_collection_report`（未収の回収報告）、`cash_deposit_report`（現金をまとめて入金した報告。現金の入金照合で伝票の組み合わせを決める）、`other`（要確認として通知）。

### 入金
- Square の振込は、三井住友なので翌営業日（土日祝・連休の分はまとめて振込）。`SQUARE_PAYOUT_BANK_TYPE = smbc_mizuho`。
- SPICE DRINK は廃業済み。それでも Square の API では毎回 Bar null の location（`L7SVX8VVWDQBX`）を指定して取得する（指定しないとメインの location だけが返る仕様のため）。
- 現金は伝票ごとに担当者が入金するのが基本。まとめて入金したときは、その報告で組み合わせを決める。
- **現金の入金は、担当者の個人口座からの振込**（2026-10-11 本人）。通帳には「振込 ＜担当者のカナ名＞」と載る。
  - 顧客からの振込（未収の回収）も「振込 ＜カナ名＞」なので、担当者のカナ名の一覧（設定）で見分ける。一覧は Phase 3 でいただく。
  - 疎通確認では、直近45日の現金決済8件に対応する振込がほぼ見当たらなかった。実際の入金が遅れている可能性がある。そのため、現金の「入金未確認」アラートが当初は多めに出るかもしれない（Phase 3 で実データを見て、猶予日数 `CASH_DEPOSIT_WINDOW_DAYS` を調整する）。

### マネフォ
- クラウド会計 API の明細一覧を、APIキー認証で読む。
- APIキーは「利用可能サービス」をクラウド会計だけにして発行する。キー自体を閲覧のみに絞る設定は無く、発行者の権限で動く。システムは読み取りの API だけを呼ぶ。

### 置き場所
- `bar-null-ops/sales/` に置く。予約対応（`src/barnull/`）とは別のパッケージ・依存関係・デプロイにする。
- 個人名を含むテストデータは `sales/samples/` に置き、git には入れない。
