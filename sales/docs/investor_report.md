# 出資者向けの月次資料（月次損益計算書）設計

状態: 実装済み（2026-11-23）。本人の依頼（2026-11-23）: 開業資金を出した出資者に見せている損益の資料を、ポータルのデータから毎月自動で作る。
ポータルに機能は足さず、ポータルと同じ Asana のデータを読む別の仕組みにする。コードは `src/barnull_sales/investor_report.py`、テストは `tests/test_investor_report.py`。

## 1. 何を作るか
- 前月分の **月次損益計算書** を A4 縦1枚の PDF にし、Google ドライブの共有フォルダに置いて、そのファイルの URL を発行する。
- 並びと書式は、本人が出資者に見せてきたスプレッドシート「YYYYMM_月次損益計算書」（共有ドライブ「5_出資者報告」。例 `202609_月次損益計算書`）に合わせる。
  表題、会社名「株式会社0x0（サザン代官山）」、期間（和暦。例「令和8年10月1日～令和8年10月31日」）、勘定科目と金額。
- 出す数字は **売上高・売上原価・販売費及び一般管理費（科目ごと）** と、そこから引き算で出る **売上総利益・営業利益** だけ。
  シートにある「配当金（出資百万円あたり）」は載せない（依頼の3項目に入らず、ポータルのデータから出す数字でもないため）。
- 顧客名・従業員名・時給・個人ごとの給与は載せない。シートの「人件費(店長)」「人件費(バイト)」は **「人件費」1行にまとめる**
  （店長の行は1人分の報酬そのものになり、個人の情報に当たるため。2026-11-23 決定）。
- 注記は「金額は税込（円）。営業日（6:00〜翌6:00）で月ごとに集計」と作成日だけ。

## 2. 項目とデータの対応（金額はすべて税込。contract.md §4 の定義に合わせる）
| PDF の行 | 元のデータ（Asana） | 決め方・補足 |
|---|---|---|
| 売上高（Bar null） | 伝票の「伝票金額」の合計（対象外を除き、未収を含む）＋ レンタルスペースの店舗収益（伝票ID が `RS-` の「入金予定額」） | シートの売上高はレンタルスペース（インスタベース・スペースマーケット）を含んでいた（経営ダッシュボードの 2026-08 の内訳と一致）。ポータルのコスト管理と同じく、レンタルは手数料を引いた **店舗収益の月次確定値** を使う。通常営業とレンタルは分けて出さない（シートに無い内訳のため） |
| 売上原価（Bar null） | 仕入（NIGITA。仕入記録ID が `P-`、「仕入金額（税込）」。返品はマイナス） | シートの売上原価＝経営ダッシュボードの「仕入費」。在庫の増減（棚卸）は反映しない（ポータルと同じ） |
| 地代家賃 | 固定費「家賃」＋「共益費」 | |
| 水道光熱費 | 固定費「ガス代」＋「設備利用費(セコム、水道、電気)」 | 実績（請求額）のタスクがあれば、その月はそれを使う（contract.md §3c） |
| 人件費 | 給与（Asana「Bar null 給与」の対象月の「給与」。区分がプロモーター以外）＋ 固定費「役員報酬」 | シートの「人件費(店長)」＋「人件費(バイト)」に当たる。**役員報酬は販管費に入れる**（会計上の費用のため） |
| 広告宣伝費 | 給与のうち区分が「プロモーター」の分（バック） | シートの「広告宣伝費」＝経営ダッシュボードの「広告宣伝費(バック)」。新しい仕組みでは、プロモーターへのバックは給与の記録に入る |
| リース費・カラオケ費・ゴミ回収費・通信費 | 固定費の同じ名前の項目 | |
| 備品・消耗品費 | 備品・消耗品（法人カード「BAR NULL」の明細。「金額（税込）」。区分「ツール・サブスク」も含む） | NIGITA の消耗品は仕入（売上原価）に入り、ここには入らない（contract.md §3b） |
| 決済手数料 | 伝票の「決済手数料」の合計（Square） | |
| その他 | 固定費の「その他」と、行の決まっていない固定費の項目 | 0 円なら行を出さない。行の決まっていない項目があれば、発行の通知で本人に知らせる |
| （入れない） | 固定費の区分「返済・配当」（出資者配当金・銀行借入の返済） | **販管費に入れない**。配当は利益の分配、借入の返済は元本の返済で、どちらも損益計算書の費用ではない（シートも入れていない）。ポータルのコスト管理は固定費に含めて見せている（contract.md §3c）ので、ポータルの利益とこの資料の営業利益は、この分だけ違う |

- 期間は営業日（6:00〜翌6:00）で数えた月。仕入は NOS の取引日、備品はカードの利用日、給与は対象月。
- 計算はポータルの `BN.ledger`（`report/portal/common.js`）と同じ規則（対象外を除く・店舗が空のものだけ）。固定費は Python の `fixed.month_amounts`（ポータルと同じ結果）。

## 3. 発行してよい条件（そろっていなければ発行しない）
ポータルの「記録済み」と同じ考え方で、次が **すべて** そろった月だけ発行する。そろっていなければ、足りないものを Slack に知らせて、翌日もう一度試す。
1. 伝票（通常営業）が1件以上あり、伝票金額が空の伝票が無い。
2. レンタルスペースの月次確定（`RS-`）が、その月かそれより後の月にある（予約対応システムが毎月1日に前月分を起票する。後の月にだけあれば、その月のレンタルは 0 円）。
3. 給与の記録がその月に1件以上あり、すべて「給与」が入っていて、**すべて「確定」**（毎月 10日 9:00 に自動で確定する）。
4. 仕入・備品消耗品が「記録済み」（contract.md §5 の 1〜4。最新の記録が月末より仕入 10 日・備品 14 日以上前なら「一部のみ」）。
5. 固定費の項目がその月にある。

## 4. 作り方と発行のしかた
- **既存の毎日のジョブ（`/jobs/daily`、毎日 10:05）に、ステップ `investor_report` を足す**。新しい定期実行は足さない（Cloud Scheduler の無料枠3本のまま）。
  10日以降で、前月分がまだ発行されていなければ、Asana を読んで集計し、そろっていれば PDF を作ってドライブに置く。費用は増えない（Cloud Run の数秒と Drive API。どちらも無料の範囲）。
- **PDF**: Python の reportlab で作る。日本語フォントは IPAex ゴシック（Cloud Run のイメージに `fonts-ipaexfont-gothic` を入れる）。手元（Windows）では BIZ UDPゴシック（ポータルと同じ）。どちらも PDF に埋め込む。
- **置き場所**: 共有ドライブ「01_飲食店事業部」の「5_出資者報告」の中の専用フォルダ（`sales.toml` の `[investor_report] drive_folder_id`）。
  ファイル名は `YYYYMM_月次損益計算書（Bar null）.pdf`。配当請求書などのある「5_出資者報告」そのものは共有しない。
- **書き込み**: sales-worker のサービスアカウント（`sales-worker@barnull-sales.iam.gserviceaccount.com`）に、専用フォルダの書き込み権限を付け、
  メタデータサーバーのトークン（範囲 `https://www.googleapis.com/auth/drive`）で Drive API v3 にアップロードする。プロジェクトで Drive API を有効にする（無料）。
- **URL**: アップロードしたファイルの URL（`https://drive.google.com/file/d/<ID>/view`）。誰が開けるかは、専用フォルダの共有設定で決まる（毎月のファイルはフォルダの共有を引き継ぐ）。§6。
- **同じ月を二度作らない**: 発行したら Firestore の `investor_reports/YYYY-MM` に「発行済み」・ファイル ID・URL を残す。フォルダに同じ名前のファイルがすでにあれば、作らずにそれを発行済みとして使う（手で置いた月や、記録の前に止まった場合）。
- **知らせ方**（どれも #null_system-monitor、メンションなし。金額は書かない）:
  - 発行したら「【出資者向け資料】YYYY年M月分の月次損益計算書を発行しました」と URL。行の決まっていない固定費の項目があれば、その補足。
  - そろっていなければ「まだ作れません」と足りないもの。同じ理由なら 3 日おき（`renotify_days`）に知らせ直す。
  - 作成・アップロードに失敗したら「失敗しました」とエラーの種類。ジョブの失敗としても数えるので、続けば障害の通知（health）も出る。
- 本人は Slack の URL を出資者に送る（送る作業は自動にしない）。

  `samples/` は git に入れない。

## 7. 2026年10月分の試作とスプレッドシートとの突き合わせ（2026-11-23）
金額つきの表は `samples/investor/reconcile_202610.md`（git に入れない。固定費・人件費の額を git に置かない決まりのため）。ここには結論だけを書く。
10月分のスプレッドシートはまだ無い（「5_出資者報告」には 202511〜202609）。そのため (a) 同じデータがある 8・9月分を項目ごとに比べ、(b) 10月分は 9月分のシートと並べた。

### (a) 8・9月分（ポータルにデータのある項目。伝票と給与は 10月から）
| 項目 | 結果 | 違いの理由 |
|---|---|---|
| 売上原価（仕入） | 8月は 1円差、9月はシートが多い | 8月は消費税の推定の端数（contract.md §3）。9月は経営ダッシュボードの 9月の仕入費が空で、シートの値の元が分からない（NIGITA 以外の買い出しなどを含めた可能性。ポータルの仕入は NIGITA だけ） |
| 備品・消耗品費 | 8月は一致、9月は違う | 9月のシートは 8月と同じ値（経営ダッシュボードの 9月が空で、8月の値のままとみられる）。ポータルはカード明細の実額 |
| 地代家賃 | シートが毎月同じ額だけ多い | 差は設備利用費と同じ額。シートは設備利用費を地代家賃と水道光熱費の両方に入れている可能性がある（シートの水道光熱費＝ガス代＋設備利用費） |
| 水道光熱費・リース費・カラオケ費・ゴミ回収費・通信費 | 一致 | |
| 人件費(店長) | ポータルに無い | 固定費の「役員報酬」は 2026-11 からで、それより前の月には無い |

### (b) 10月分の試作
- 売上高・売上原価・備品・決済手数料・固定費の各行は、ポータルのデータから出た（月が違うので 9月のシートとは比べられない。地代家賃の差は上と同じ）。
- **人件費・広告宣伝費が 0（未記録）**: 10月の給与の記録が無い（「Bar null 給与」は 0 件。勤怠の記録は 2026-11-21 から）。役員報酬は 2026-10 からに直した（2026-11-23）。
  このため営業利益が大きく出ており、**このままでは出資者に出さない**。PDF には「試作」の印が付く。
- 10月分は、給与の記録がそろうまで発行しない（§3 の 3）。本人が「Bar null 給与」に 10月分を入れれば、次の毎日のジョブか手元のコマンドで発行できる。
- 11月分: `payroll_since` を 2026-11 にした（2026-11-23 本人の指示）。12/2 17:00 に、勤怠の記録がある日の時給分と 11月全体のバックが自動で計算される。勤怠の記録が無い 11/1〜20 の時給分は、本人がその人の給与タスクの「調整額」で足す（12/10 9:00 の確定・10:05 の発行より前に）。
- 役員報酬（固定費、手入力のタスク）は出資者向けシートの「人件費(店長)」と同じもの（2026-11-23 本人確認）。10月分に入るよう、適用開始月を 2026-10 に直した（本番・テスト。2026-11-23）。
