# Phase 4 報告（未収・訂正・手動対応）

- 完了: 2026-10-17
- 範囲: 依頼書 §5.5（未収）、§5.7（手動対応）、§5.8（訂正）、現金のまとめ入金の報告、古いイベントの削除

## 作ったもの（`followups.py`）
- 訂正（@Bot の訂正メッセージ）
  - 送った人の、24時間以内の伝票に当てる。顧客名が書かれていれば、それで絞る。決められなければ「要確認」。
  - 金額・顧客名を変更し、変更前→変更後をスレッドに書く。金額が変わったら、Square の割り当てを外して照合し直す。
  - 完了済みの伝票への訂正は、自動では開き直さず「★完了後の訂正」で知らせる。
- 未収の回収
  - 回収報告（@Bot）: 顧客名（同名が複数なら金額）で未収の伝票に当て、「回収報告済み」にする。報告者・内容・日付をスレッドに残す。
  - 銀行の振込: 三井住友の「振込 ＜名義＞」が未収残高（または報告額）と一致し、名義と顧客名が同じ人だと Claude（Haiku）が確信度 0.8 以上で判定すれば「回収入金確認済み」にする。
    - 判定できなければ「回収の振込か不明」として知らせる。
    - Square の振込と、担当者の名義（現金の入金）は対象外。
  - 後日の Square 決済: 営業日の翌日以降に、未収残高と同じ金額の決済があれば割り当てる。その振込の着金を確認したら「回収入金確認済み」にする。
  - 一部回収: 未収残高を減らしていく。残高が0になったら「回収入金確認済み」。入金も確認済みなら完了にする。
  - リマインド（毎日 10:00）: 起票から7日ごとに、スレッドで桝本をメンションする（顧客名・未収残高・経過日数・状況・担当）。
- 手動上書き（Asana の「手動上書き」欄。30分ごと）
  - 決済確認済み／入金確認済み／未収回収済み／対象外（取消）を反映し、誰がいつ変えたかをスレッドに書く。
  - 反映したら欄を「なし」に戻す。対象外（取消）は Square の割り当てを外し、Asana のタスクを完了にする。
- 現金のまとめ入金の報告（@Bot）
  - 報告に挙がった顧客の現金の伝票の合計と、振込（担当者の名義の一覧があれば、その名義に限る）を照合する。
- 古いイベントの削除（毎日 10:00）: 受け取ったイベントの記録を30日で消す。
- 安全のための調整
  - 全額未収の伝票では、Square の決済を探さない。期待額は0未満にしない。
  - 完了・取消・手動で決済確認済みにした伝票は、決済の照合の対象から外す。
- テスト: 単体テスト計45件（訂正と照合のやり直し、完了後の訂正、回収報告→振込の着金→完了、名義が不明な振込、後日の Square 決済での回収、リマインドの周期、手動上書き、現金のまとめ入金）。

## 動作確認（テスト用グループ・チャンネル・プロジェクト）
| 確認 | 結果 |
|---|---|
| 全額未収の伝票（テスト二郎さま 50,000） | 【未収あり ¥50,000】で起票。Square の照合はしない（skip） |
| 回収報告「テスト二郎さまの未収5万、振込ありました」 | 対象の伝票に当たり、「回収報告済み」。スレッドに報告を記録 |
| 訂正「さっきのテスト様、12,000でした」 | 送った人の伝票（12,345）に当たり、¥12,345 → ¥12,000。照合をやり直した |
| Asana の手動上書き（Claude が API で「対象外（取消）」に変更） | 次の照合で反映。スレッドに記録、タスクを完了、欄は「なし」に戻った |
| 未収リマインド（間隔を一時的に約4分に短縮） | テスト二郎さま・顧客Cさまのスレッドにリマインド（桝本メンション）。確認後に7日へ戻した |

## 残り
- 現金の自動照合と現金のまとめ入金の照合は、担当者の名義の一覧をいただいてから本格的に動く（一覧が無いあいだも、まとめ入金の報告は「Square 以外の振込で合計が一致し、候補が1件」なら照合する）。
