### マネフォについて
- 本人が想定している「カスタムコネクタ」は、Claude にマネフォの MCP サーバーをつなぐ方法のこと（開発中の確認には使える）。
- 本番の Cloud Run からは同じデータを REST API で読む。どちらも同じ APIキーで動く。
- APIキーの権限は、発行したユーザーの権限と同じになる。発行の画面で選べるのは「利用可能サービス」だけで、閲覧のみに絞る設定は無い（アプリポータルのガイド、2026-08-25 更新）。クラウド会計だけを選んで発行し、システムは読み取りの API だけを呼ぶ。
- 銀行明細がマネフォに入るのは1日1回程度で、1〜2日遅れることがある。入金の照合は1日数回で足りる（30分ごとのジョブでは、マネフォの照合を数時間おきにだけ行う）。
- 公式の API リファレンスは今回の調査ツールで本文を読めなかった。パラメータ名は、APIキー発行後に実際に1回呼んで確定する。

- Cloud Storage は使わない（画像を扱わなくなったため）。
- 課金停止の仕組みの注意
  - 課金データの反映は数時間遅れるので、止まるまでに数円かかる可能性はゼロにはできない。
  - 止まるとシステム全体が止まる。止まる前に Slack とメールで知らせ、再開は原因を確認してから手動で行う。

- 無料枠は「請求先アカウント単位」で合算される。同じ請求先アカウントに他のプロジェクトがあると、Scheduler の無料3ジョブなどを共有する（確認事項）。
- 依頼書の構成のまま（Secret を10個、GCS を東京）だと月50〜130円程度かかる。上の調整で0円にできる見込み。
- LINE は Webhook の応答を2秒しか待たない。Cloud Run が止まっている状態からの起動は約3秒かかることがある。
  - そのため LINE の Webhook 再送を ON にし、`webhookEventId` で重複を除く（再送されても二重に処理しない）。
  - Webhook の入口は読み込むライブラリを最小にして、起動を速くする。

### 伝票の写真

| サンプル | 内容 | 結果 |
|---|---|---|
| ③ 顧客Bさま・顧客Cさま | 2枚並べ、明るい | **全モデル・全方式で正解**（24,750 / 57,750、顧客名も読めた） |
| ① 顧客Aさま | 1枚、赤い照明、Total に取り消し線と書き直し（106,000 → 100,000） | 割れた。Haiku は 40,000（明細の行）や「読めない」が多い。Sonnet は全体では正解したが、切り出すと取り消し線の 106,000 を読んだ |
| ② 顧客Dさま | 7枚並べ、90°回転、1枚が小さい | どの方式でも全部は読めない。読めた範囲の合計は 64,500〜65,000 前後 |

- 写真1枚あたりの費用: Haiku ¥0.08〜0.3、Sonnet ¥1.5〜2.1。伝票1枚ずつ切り出して読む方式は、費用が増えるわりに改善しなかった。
- **②はメッセージの金額（71,700）と合わない**。人の目で切り出し画像を見ても、各伝票は 8,800 / 8,800 / 7,700 / 11,000 / 11,100（Uber 1,200 込み）/ 9,900 / 7,700 と読め、合計は 65,000 になる。
  - 6,700 の差は、読み違いでは説明しにくい。伝票に無い分がメッセージの金額に含まれている可能性がある。
  - 本番ではこのケースで「金額不一致」が出る。Square の 10/3 の決済額と照らして、どちらが正しいか確認したい（確認事項）。
- テストの画像は、チャットに添付されて縮小された版（長辺 1,477px）。実際に LINE で受け取る画像はこれより大きい可能性があるので、元の画像でも試したい（確認事項）。

### 読み取りの方針（決定事項 2）
- 写真はまず Haiku で読む。メッセージの金額と合えば確定する。
- 合わないときだけ Sonnet で読み直す。それでも合わなければ「金額不一致」のアラートを出す。
- 読み取りは、スタッフの入力ミスに気づくための確認。金額が正しいかの最終判断は Square との突合で行う。
- スタッフ向けガイドには「白い照明の下で、伝票を1〜2枚ずつ真上から撮る」を推奨として入れる（強制はしない）。

### Claude API の費用見込み
- 伝票1件: Haiku だけで済めば **約¥0.15**（写真 ¥0.1 前後＋メッセージ ¥0.04）。Sonnet で読み直すと **約¥2.2**。
- 月60件で読み直しが3割なら **月50円前後**。月300件なら月250円前後。

## 4. 各サービスの仕様で依頼書と違った点（要約）

- **LINE**
  - 公式アカウントの開設には LINE ビジネスID と「ビジネスマネージャー組織」との接続が必要（2025-06 から）。
  - グループメンバーの ID 一覧 API は認証済みアカウント専用。ただし、個別のプロフィール取得（表示名）は使える見込み。
  - Webhook の再送は回数・期間が非公開で、届く保証もない。画像はいつまで LINE に残るかが保証されないので、受け取ったらすぐ保存する。
  - 1回に複数枚送った画像には `imageSet`（id・index・total）が付く。届く順番は index 順とは限らない。
- **Square**
  - ListPayments・ListPayouts は location を指定しないとメインの location しか返さない。
  - Payout の明細（entries）から `payment_id` を辿れる。
  - Payouts API が日本で使えるかは公式に明記がない（疎通確認で確かめる。使えなければ依頼書のフォールバック）。
  - 振込の通帳名義は「スクエア (カ」。
- **Asana**
  - 無料プランではカスタムフィールドが使えない（今回は有料プランなので問題なし）。
  - PAT は発行した本人の権限になり、無期限。
- **Slack**
  - 無料プランは90日より古いメッセージを見られない（台帳は Asana）。
  - `chat.update` でメンションを足しても通知されない可能性が高いので、通知はスレッド返信で行う。

## 5. リスク

| リスク | 影響 | 対策 |
|---|---|---|
| @Bot を付け忘れたメッセージ | 伝票が起票されない | スタッフ向けガイドで周知。Square に決済があるのに伝票が無いときに通知する（2026-10-10 追加） |
| 課金停止が働いた | システム全体が止まる | 止まる前に Slack とメールで通知。手順書に再開手順を書く |
| 起動の遅さと LINE の2秒制限 | Webhook がタイムアウトする | 再送を ON にし、eventId で重複を除く。入口を軽くする |
| マネフォへの明細反映の遅れ（1〜2日） | 入金確認が遅れる | 入金の猶予（`DEPOSIT_GRACE_BIZDAYS` = 3営業日）で吸収 |
| マネフォ API の項目名が未確定 | 実装の手戻り | APIキー発行後、Phase 0 の疎通確認で確定する |
| Payouts API が日本で使えない可能性 | 振込額を計算で求める必要 | 依頼書のフォールバック（振込サイクルから合計を計算） |
| 無料枠を他のプロジェクトと共有 | わずかな課金 | 請求先アカウントの他のプロジェクトを確認。予算アラート |
