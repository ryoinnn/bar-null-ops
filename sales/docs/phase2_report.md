# Phase 2 報告（Square との突合）

- 完了: 2026-10-17
- 範囲: 依頼書 §5.3、伝票の無い決済の通知（decisions.md）

## 作ったもの
- Square の読み取り専用 OAuth（`/oauth/square/start` → 許可 → `/oauth/square/callback`）
  - 許可の範囲は PAYMENTS_READ・ORDERS_READ・PAYOUTS_READ・MERCHANT_PROFILE_READ。
  - Bar null の加盟店（MLW68WPW3T15S）以外からの許可は拒否する。
  - トークンは Secret Manager の `square-oauth` に置く。期限まで7日を切ったら更新し、古い版は破棄する。2026-10-17 に本人が許可した。
- 突合（`matching.py`・`reconcile.py`）
  - 起票直後に1回、その後は Cloud Scheduler `sales-reconcile`（30分ごと）で照合する。
  - 照合の順番: 金額が一致する1件 → 30分以内の最大5件の合計（割り勘）→ 候補が複数なら要確認 → 指定の営業日の外にだけあれば「日付ズレ疑い」。
  - 同じ金額の伝票が同じ日に複数ある場合は、伝票の数までなら時刻の早い順に割り当てる。
  - 期待額は「伝票金額 − 未収額」。未収があるのに全額の決済があれば「★金額不一致」（未収の前提と違う）。
  - 送信から60分たっても決済が無ければ「★決済未確認」。3日間は探し続け、見つかれば自動で解消する。
  - 割り当てた決済は `payment_claims` に記録し、二重には使わない。
  - 割り当て済みの決済に返金があれば「★返金検知」。
- 伝票の無い決済の通知
  - 対象: Bar null の COMPLETED の決済で、どの伝票にも割り当てられず、全額返金されていないもの。
  - 営業日が終わってから6時間たったら、チャンネルに1回だけ投稿する。あとで割り当てられたら、その通知のスレッドに「解消」と返信する。
  - 稼働開始（`orphan_check_since`、現在 2026-10-17 15:00）より前の決済は対象外。
- 反映: スレッドに「決済確認済み：Square ¥…（日時 支払手段）手数料 ¥…」と返信し、親メッセージのステータス行を更新する。Asana は「決済確認済み」セクションに移し、Square決済額・決済手数料・Square payment ID を記入する。
- テスト: 単体テストは計29件（照合の各パターン、起票直後の突合、未収の控除、決済未確認と解消、2人分の割り当て、伝票の無い決済の通知と解消、返金、未収の前提違い）。

## 動作確認（テスト用グループ・チャンネル・プロジェクト、Square の実データ）
| 伝票 | 結果 |
|---|---|
| 10/5 顧客Aさま 100,000 | 起票直後に 10/06 05:28 の Amex 100,000（手数料 2,500）に割り当て → 決済確認済み |
| 9/28 顧客Bさま 24,750（Phase 1 のテスト分） | 定期の照合で 9/28 22:35 のカード決済に割り当て → 決済確認済み |
| 9/28 顧客Cさま 57,750（テスト文面で「4万円未収」と書いた分） | Square には全額 57,750 の決済がある → ★金額不一致（未収の前提と違う）。テスト文面が実際と違うためで、正しい動き |
| 10/16 テスト様 12,345（存在しない金額） | 待ち時間を一時的に5分にして、★決済未確認（スレッドとチャンネル、桝本メンション）。確認後に60分へ戻した |

- 伝票の無い決済の通知は、稼働開始後に実際の決済が入ったときに確かめる（単体テストでは確認済み）。
- 実データで見ると、10/3 顧客Dさま 71,700 に一致する決済は無い（本番なら決済未確認になるケース）。
