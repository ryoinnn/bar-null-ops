# 要件定義: 仕入管理（セッション C）

状態: **確定・本番稼働**（2026-11-15 本人了承「推奨どおりで実装」、同日本番化。本番プロジェクト `1220540183336163`）。データの約束は contract.md §3、運用は runbook.md「仕入」。

## 1. 目的と範囲
- 酒屋 NIGITA の発注サイト NOS（https://order.nigita.co.jp/oms/login）の「仕入実績一覧」を、毎週月曜の朝に読み取って Asana に記録する（2026-11-15 本人指定で日次から変更）。
- ポータルの「コスト管理 > 仕入管理」（`#cost-purchase`、`sales/report/portal/pages/purchase.html`）で、次を行う。
  - 仕入のダッシュボード
  - 商品別の詳細
  - 商品マスタ（表示名）の入力
- 仕入の合計は、売上管理の利益（変動費）に使う（A が読む）。
- 対象は Bar null（NOS の得意先「ｎｕｌｌ（代官山町）」）だけ。福岡 Node と、NIGITA 以外の仕入先は、項目で区別できる形にだけしておく。

## 2. 確認できた NOS の事実（2026-11-15、読み取りのみ）
- **規約**: ログイン画面、マイページ、NIGITA の会社サイト（NOS の案内ページを含む）に、利用規約・自動操作の禁止条項は見当たらなかった。
  「操作マニュアル」（ダウンロード）は開いていない。
- 画面: マイページ（`/oms/myPage`）→「仕入実績一覧」（`/oms/stockingResults`）。取引日の既定は当月1日〜月末。
  「総合計金額を表示する」にチェックを入れて「検索」を押すと、合計金額（税抜）・消費税・総合計金額（税込）と明細の表が出る。
- 明細の列: ステータス、取引日、伝票番号、注文番号、JAN コード、商品コード、商品名、**カテゴリ名**、入数、規格、販売単位、注文数量、**仕入数量**、仕入単価、**仕入金額（税抜）**
- 表は DataTables で、画面のページ送りに関係なく全行を一度に読める。
- データは 2026-08-09 から存在する（8〜10月で77行、28伝票、18日、26商品）。
- ステータスは「出荷確定（完納）」「出荷確定（欠品有）」「欠品」の3種類。欠品は仕入数量・仕入金額に反映済みなので、仕入数量・仕入金額をそのまま使う。
- **返品**は、元の伝票を直す形ではない。数量・金額がマイナスの別伝票（注文番号なし）として出る。
- 注文番号のない伝票がある（電話などの Web 以外の注文や返品）。1つの注文番号に複数の伝票が付くことがある。
- **消費税**は伝票ごとには出ない。行ごとに「飲料・調味料 8%、それ以外 10%」として計算すると、画面の消費税と1〜2円差で一致した。
- 画面に注文ボタン（数量・カート・注文確定）があるページもあるが、仕入実績一覧には無い。

## 3. 取得の方式
```
Windows タスクスケジューラ（本人の PC。毎週月曜 9:30）
  └ uv run barnull-sales purchase-fetch …… Playwright で NOS を開き、仕入実績一覧を検索して表を読む（読み取りだけ）
      ├ 結果を PC に保存（sales/samples/purchases/。git に入れない）
      ├ 新しい商品の表示名を Claude Haiku（最新版）で付ける（商品名だけを渡す。API キー → PC の Claude Code の順）
      ├ Asana に冪等に書く
      └ Slack #daily_barnull-sales に結果を短く知らせる
```
- **推奨: Playwright（決まった手順のプログラム）**。リポジトリの予約対応（`src/barnull/`）と同じ方式にする。理由は次のとおり。
  - 仕入実績一覧は1画面・1回の検索で、表を丸ごと読める
  - Claude in Chrome に毎回ページを操作させるより、速く、壊れにくく、Claude の利用枠も使わない
  - Claude は商品名を整えるところだけに使う
- ログイン: NOS のセッションはすぐ切れる（`/oms/error?timeout`）ため、本人が `purchase-set-login` で資格情報マネージャーに登録した
  ID・パスワードで、プログラムが自動でログインし直す（予約対応と同じ方式）。Claude はパスワードを見ない・入力しない。
  認証コード等の追加の確認が出たら止めて知らせる。
- 期間: 当月1日〜本日。毎月1〜7日の実行では前月1日から読む。初回だけ 2026-08-01 から読む（過去分の取り込み）。
  毎回、期間内を全件読み直して上書きするので、二重記録や修正の漏れは起きない。
- 操作するのは、取引日の入力・チェックボックス・検索ボタンだけ。注文・カート・設定・パスワード変更などには触れない。
- クラウドには何も足さない（課金は発生しない）。PC が止まっていた日の分は、次に起動したときに実行する（期間で読むので取りこぼさない）。

## 4. 商品名の標準化と商品マスタ
- 新しい商品コードが出てきたら、表示名の案を作る。
  - 例: 「アイリスオーヤマ とうもろこしのひげ茶 １．５Ｌ」→「ひげ茶」、「クエルボ１８００アネホ ４０°７５０ｍｌ」→「クエルボ1800アネホ」
  - 規則: メーカー名・容量・度数・入数・「※」「☆」などの記号を落とし、全角英数を半角にする。銘柄が分かる最短の名前にする。
  - Claude（Haiku）に渡すのは商品名だけ（価格・数量は渡さない）。
- 区分は NOS のカテゴリ名から自動で決める（Claude は使わない）。

  | 区分 | NOS のカテゴリ名 |
  |---|---|
  | 酒類 | 焼酎、ビール類、果実酒、ウイスキー、スピリッツ、リキュール |
  | ソフトドリンク | 飲料 |
  | 食材 | 調味料 |
  | 消耗品 | 雑貨販促品類、備品類 |
  | その他 | 上記以外（新しいカテゴリが出たら Slack で知らせる） |

- 商品マスタの1件は、商品コード・元の商品名・表示名・区分・確認状態からなる。
- 確認状態は「案（自動）」か「確認済み」。本人が画面で直して保存すると「確認済み」になり、以後は自動で上書きしない。
- 集計（ランキング・詳細）は表示名でまとめる。容量違いなどに同じ表示名を付けると合算される。

## 5. 記録（Asana）
プロジェクト「Bar null 仕入」（本番）と「Bar null 仕入（テスト）」。セクションは「仕入」「要確認」「対象外」「商品マスタ」。

### 5.1 仕入（1タスク = 1伝票）
| 項目 | 型 | 内容 |
|---|---|---|
| 記録ID | テキスト | `P-{取引日 YYYYMMDD}-{伝票番号}`。重複防止のキー |
| 営業日 | 日付 | 取引日（日付だけなので、そのまま営業日とする） |
| 仕入先 | テキスト | `NIGITA` |
| 伝票番号 / 注文番号 | テキスト | NOS の値（注文番号は空のことがある） |
| 金額（税抜） | 数値 | 仕入金額の合計。返品はマイナス |
| 消費税（推定） | 数値 | 行ごとの税率（§2）で計算 |
| 金額（税込） | 数値 | 税抜 ＋ 消費税（推定） |
| 品目数 / 数量 | 数値 | 仕入数量の合計 |
| 品目の要約 | テキスト | 表示名で「クエルボ1800アネホ 4ほか3品」のように書く |
| 仕入ステータス | 選択 | 取り込み済み／要確認（区分の分からない NOS カテゴリ）／対象外（NOS から消えた伝票）。欠品は要確認にせず件数を表示する |
| 店舗 | テキスト | 空（Bar null） |

- 明細は、タスクの本文に決まった形式で書く（1行1品: 商品コード・商品名・カテゴリ・仕入数量・単価・金額・ステータス）。画面はこれを読む。
- 読み直したときに NOS から消えていた伝票は、「対象外」にする（削除しない）。
- 期間ごとの NOS の合計（合計金額・消費税・総合計）と、記録した伝票の合計を照らし合わせる。
  - 税抜が合わない場合は、要確認として知らせる。
  - 消費税の差が数円なら、端数処理の差として扱う。

### 5.2 商品マスタ（1タスク = 1商品）
記録ID `M-{商品コード}`、元の商品名、表示名、区分、NOS カテゴリ、確認状態、初回の取引日。

## 6. 画面（ポータル `#cost-purchase`）
- 左のサイドバー: 売上管理と同じく、年→月→週で切り替える（週は月曜〜日曜、月をまたぐ週は月で区切る）。
- ダッシュボード（選んだ期間）
  - 発注の合計金額（税込。税抜も併記）。前の期間の同じ日数までと比べる
  - 1回あたりの発注額: 合計 ÷ 発注回数。発注回数は取引日（納品日）の数とする（Q1）
  - 発注数ランキング TOP5（表示名ごとの仕入数量。同数なら金額の順）
  - 区分ごとの金額、返品・欠品の件数
  - AI の示唆: 売上管理と同じく、押したときに集計値だけを Claude に渡す。結果は Artifact の db（`purchase_insights`）に保存する。db の規則の追加は A に依頼する
- 商品の詳細（ランキングから移る）: その期間に発注があった商品だけを表示する。
  - 列は、表示名・数量・金額（税抜）・発注回数・区分
  - 並べ替えができる
- 商品マスタ: 一覧で表示名・区分を直して保存する（ポータルの Asana 書き込み `update_tasks` を使う）。「案（自動）」を上に出す。
- データは、開いた人の Asana コネクタでその場で読む（売上管理と同じ）。コスト管理は Editor 以上にだけ表示される。

## 7. 失敗の知らせ方
- 毎回、Slack（#daily_barnull-sales）に短く知らせる。内容は、取り込んだ伝票数、期間の合計、新しい商品の数、要確認の件数。
- ログイン切れ、画面の変化（列が変わった等）、合計の不一致は「★」付きで桝本さんをメンションする。
  ログイン切れのときは、再ログインの手順（1行のコマンド）も書く。
- Slack に送れないときは、PC の通知とログファイルに残す。

## 8. 守ること
- 価格・商品・伝票の情報は git に入れない（`sales/samples/` 配下と Asana だけに置く）。
- Claude に渡すのは、商品名（名前の標準化）と集計値（AI の示唆）だけ。
- 実装後は、テスト用プロジェクトで動かして本人が確認してから、本番にする。
