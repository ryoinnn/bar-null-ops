# 要件定義: 備品・消耗品費（セッション D）

状態: **確定**（2026-11-15 本人了承「このまま実装」）。実装済み。データの約束は contract.md §3b、運用は runbook.md「備品・消耗品」（実装後）。

## 1. 目的と範囲
- 備品・消耗品（グラス、おしぼり、洗剤、紙類、小物、ツール類など）の購入費を、**マネーフォワード クラウド会計に連携済みの法人カード「BAR NULL」の明細から自動で拾い**、Asana に記録する。
- 利益の変動費の「備品消耗品管理」の箱（ポータル `#cost-supplies`）に出す。
- 対象は Bar null。福岡 Node は対象外（「店舗」の項目で区別できる形にだけしておく）。

## 2. 本人の回答（2026-11-15）
- 購入先ごとではなく、**備品消耗品用のカード（マネフォのビジネスカード「BAR NULL」）の決済額**を参照する。
- 支払いは会社カード＋マネフォ。記録の入口は **マネフォのカード明細から自動**（手入力なし）。
- **私的利用は認めていない**ので、カードの明細はすべて備品消耗品費に計上する（個別の選別をしない）。
- 月額の目安は 1〜3 万円。

## 3. 確認できた事実（2026-11-15、読み取りのみ）
- マネフォ API の「連携口座」に、ビジネスカードの利用者別の補助口座が並ぶ（BAR NULL、個人名義のカード3枚、残高、ポイント）。「BAR NULL」の補助口座だけを読む。
- 明細の項目: id、date（利用日）、value（円）、side（EXPENSE ＝ 利用、INCOME ＝ 返金など）、content（摘要 ＝ 店名）、journalizing_status。
- 直近 90 日の「BAR NULL」: 32 件・約 27.7 万円（月あたり約 9 万円）。**目安の 1〜3 万円より多い**。摘要には Amazon、コンビニ、家電量販店、文具店、ほかに AI サービス（Anthropic）の月額、ロケットナウなどが混ざる。
  → 「すべて備品消耗品費」でよいが、ツール・サブスク（AI など）は区分を分けて、画面で内訳が見えるようにする（§5）。
- カード明細は、利用から 1〜2 日遅れて入る。「PENDING」（速報）の明細が、確定時に別の id・別の摘要で置き換わることがある（Uber Eats など）。
- 銀行口座（三井住友）にはカードの引落（まとめて1件）が別に出る。**読むのはカードの補助口座だけ**なので、引落と二重にならない。

## 4. 区分の境界（仕入との線引き。重複計上の回避）
| 何を買ったか | どこで買ったか | 入る先 |
|---|---|---|
| 酒・飲料・食材、および NIGITA（NOS）の雑貨・備品類 | 酒屋 NIGITA（NOS） | **仕入**（区分「消耗品」はここ。仕入のほうに数える） |
| グラス・おしぼり・洗剤・紙類・小物・ツール類 | **カード「BAR NULL」の利用** | **備品・消耗品**（この要件） |

- 約束: **NIGITA への支払いは備品・消耗品に入れない**（2026-11-15 本人「仕入は仕入れで分けて管理したい。消耗品とは混ぜない」）。NIGITA は銀行振替で支払うため、通常はカードに出ない。万一カードに出たときのため、摘要に NIGITA を含む明細は自動で「対象外」にする（設定 `exclude_patterns`）。
- 仕入の「消耗品」区分（NOS の雑貨販促品類・備品類）と、備品・消耗品（カード）は別の金額。**変動費の合計は両方を足してよい（重複しない）**。画面は、備品消耗品の箱に「カード分」だけを出し、仕入の消耗品は仕入の箱に残す。
- 個人名義のカード（3枚）は読まない。そちらに備品を載せたものは、本人が Asana に手入力で足す（§6「手入力」）。

## 5. 記録
- 1 明細 ＝ 1 タスク。Asana の非公開プロジェクト「Bar null 備品消耗品」（管理者だけ。本番とテストの2つ）。
- 記録 ID は `E-{営業日 YYYYMMDD}-{連番3桁}`。**同じ明細からは二度作らない**（冪等のキーはマネフォの明細 id。Asana の「MF明細ID」の項目に持つ）。
- 営業日: 明細の利用日（日付だけなので、そのまま営業日とする。仕入と同じ扱い）。
- 金額は **税込**（カードの請求額）。返金は **マイナス**。消費税の内訳は持たない（利益は税込で統一。contract.md §4）。
- 備品区分（選択。スタッフ台帳の「区分」と別の欄）: **備品・消耗品**（既定）／**ツール・サブスク**（摘要が設定 `tool_patterns` に当たるものを自動。Anthropic、OpenAI、Slack など）／**その他**。本人が Asana で直せる。直したものは同期で上書きしない。
  - 備品と消耗品は**分けない**（1つの箱）。理由: 個々の品目が明細に出ない（店名しか分からない）ので、自動では分けられず、利益への影響もない。
- 固定資産・減価償却: **扱わない**。1 件 10 万円以上の利用は、記録は同じにしてポータルの「高額」の件数に出し、本人が固定費（減価償却）として扱うか決める（設定 `high_value`）。
- 状態: **取り込み済み**／**対象外**。取消 ＝ 状態を「対象外」にする（削除しない。Asana で本人が直す）。
- マネフォから消えた明細（PENDING の置き換えなど）は、同期が「対象外」にする（読んだ期間内のものだけ）。

## 6. 取り込みと訂正
- **取得**: 既存のクラウドの定期ジョブ（`/jobs/reconcile`、30 分ごと）の中のステップ `supplies` に足す（新しい定期実行は足さない。課金は増えない）。マネフォを読むのは **3 時間に1回**（入金照合と同じ）。
  - 読む期間: 今日から 60 日前まで。初回だけ 2026-08-01 から読む（過去分の取り込み）。毎回、期間内を全件読み直して Asana に合わせる。
  - 取り込みの結果は Slack に知らせない（2026-11-15 本人「備品消耗品費の情報取得に関する Slack 通知は必要ない」。`notify = false`）。失敗だけは既存の health の仕組みが ★ 付きで知らせる。
- **訂正**: Asana のタスクで、営業日・金額・区分・支払先を直し、「手動修正」を「あり」にする。「あり」のタスクは同期で上書きしない（対象外にもしない）。
- **取消**: 状態を「対象外」にする。同期は「対象外」を取り込み済みに戻さない。
- **手入力**（個人カード・現金立替など）: Asana にタスクを足し、「取得元」を「手入力」、営業日・金額・支払先を入れる。手入力のタスクは同期の対象外（触らない）。記録 ID は空でよい。
- 本人のログインや認証コードは要らない（マネフォは既存の API キー）。
