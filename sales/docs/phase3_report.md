# Phase 3 報告（入金の確認）

- 完了: 2026-10-17（現金の自動照合は、担当者の名義の一覧をいただくまで止めている）
- 範囲: 依頼書 §5.4

## 作ったもの
- Square の振込（payout）の特定（`SquarePayouts`）
  - 決済を含む振込を、振込の明細（entries）の `payment_id` から探す。
  - 振込の明細は Firestore の `payouts` にキャッシュする（一度取れば変わらないため）。
  - 振込がまだ作られていない決済は、次の回に回す。
- マネフォの入出金明細（`MoneyForward`）
  - APIキー → JWT（1時間キャッシュ）。三井住友の口座の `side = INCOME` だけを読む。
  - 取得は3時間ごと（`mf.fetch_interval_hours`）。
- 照合（`deposits.py`）
  - カード等: 振込額と同じ金額で、摘要に「スクエア(カ」を含み、日付が「着金予定日の前日〜予定日の3営業日後」の入金。
    - 1つの入金で、その振込に含まれるすべての伝票を確認済みにする。
    - 使った明細は `deposit_claims` に記録し、二重には使わない。
  - 現金: 担当者の名義（`mf.staff_bank_names`）を含む振込のうち、決済から14日以内で金額が一致するもの。一覧が空のあいだは照合しない。
  - すべての入金を確認したら「入金確認完了」。未収が無い（または回収入金確認済み）なら完了にする（Slack に「完了」、Asana のタスクを完了、`closed_at`）。
  - Asana の入金予定額（その伝票の取り分: 決済額 − 手数料）と入金日を記入する。
- 「★入金未確認」（Cloud Scheduler `sales-daily`、毎日 10:00）
  - カード等: 着金予定日の3営業日後を過ぎても入金が無い。
  - 現金: 決済から14日を過ぎても振込が無い。名義の一覧が未設定であることも文面で知らせる。
- 30分ごとのジョブ（`sales-reconcile`）で、決済の突合に続けて入金の照合を行う。
- テスト: 単体テスト計37件（振込の確認と完了、合算振込で複数の伝票、金額・摘要が違う入金は使わない、入金未確認の猶予（祝日を挟む）、振込が未作成なら待つ、現金は名義の一覧があるときだけ、未収が残る伝票は完了にしない、マネフォ取得の間引き）。

## 動作確認（テスト用プロジェクト、Square とマネフォの実データ）

| 伝票 | 結果 |
|---|---|
| 10/5 顧客Aさま 100,000 | 振込 97,500（予定 10/08）→ 三井住友 10/07「振込 スクエア(カ フリコミ」97,500 で確認。入金確認完了 → 完了。Asana のタスクも完了 |
| 9/28 顧客Bさま 24,750 | 振込を特定し、銀行の入金で確認。入金確認完了 → 完了（入金予定額 24,131、入金日 9/29） |

- Cloud Scheduler は2本（`sales-reconcile` 30分ごと、`sales-daily` 毎日 10:00）。無料枠（3本）の範囲。
